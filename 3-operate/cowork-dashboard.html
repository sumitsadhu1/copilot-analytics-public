Operational views, not the bill

Use these dashboards to track adoption, value, and spend trends. Reconcile charges against the monthly billing record (Billing > Bills & payments in the Microsoft 365 admin center), never against a dashboard. Report Cowork assisted hours as a directional estimate only, not as time saved, a productivity gain, a business outcome, or realised value.

1. Which Dashboard Answers Which Question

Cowork reporting is split across two products. The Microsoft 365 admin center covers adoption, access, and value. The Viva Insights Consumption Dashboard covers credit consumption by organisation, group, and job function. Start from the question you need to answer.

QuestionWhere to lookNotes
How many people use Cowork, how often, and do they come back?Admin center: Copilot > Cowork > UsageDefaults to the past 28 days. Each card shows a week-over-week trend.
Who is using it, and how much?Admin center: Cowork usage details table on the Usage tabOne row per user with activity since 1 April 2026. Exports to CSV.
What work does Cowork do, and how many hours did it assist?Admin center: Copilot > Cowork > ValueFrontier preview. Assisted hours are directional (Section 5).
Who is waiting for access, and is a billing grace period running?Admin center: Copilot > Cowork > OverviewAlso links to Cowork plugin management.
How many credits does Cowork consume, and which groups drive it?Viva Insights: Consumption Dashboard > Microsoft 365 services > Cowork (Deep dive)Month to date, filtered by Scope, Organization, and Job function. The services page currently covers only Cowork and the Work IQ API.
Can I query Cowork data in Advanced analysis?Advanced analysis consumption queryReturns four preselected metrics (Total Copilot Credits used, Session count, User limit, and Spending policy limit) and excludes GitHub data. Every Cowork metric in the metrics reference, including tasks, task categories, and assisted hours, is listed for the Consumption Dashboard only, so don’t plan queries around them.

Only the Value tab is labelled preview. Microsoft’s articles don’t label the other admin center tabs or the Consumption Dashboard’s Cowork page as preview.

Don’t use the Agent Dashboard for Cowork. Microsoft is moving Cowork usage data out of it into other Viva Insights reports and points to the admin center in the meantime.

2. Access and Scope

Two separate controls apply. Spending policies decide who can use Cowork. Reporting roles decide who can see the dashboards.

Spending policies grant Cowork access

Anyone in scope of a spending policy that includes Cowork can use it, whatever the policy’s credit limit. The Cowork entry under Agents > All Agents doesn’t control access. The default first-time usage-based billing setup targets your whole organisation, so decide who should get Cowork before you complete it. For a pilot, select Customize setup configuration during setup to limit the default policy to specific groups.

Admin center reporting roles

To read the Cowork dashboard, use a role that can view Microsoft 365 usage reports. For read-only access, assign Reports Reader. AI Administrator, Global Administrator, Exchange Administrator, SharePoint Administrator, Teams Administrator, and Teams Communications Administrator can also view it. Usage Summary Reports Reader and User Experience Success Manager are limited to reports without user details, so check what they see in the Cowork table before you rely on them. Global Reader isn’t on Microsoft’s usage-report role list, so don’t assume it works.

The Cowork article doesn’t document separate role requirements for the Value or Settings tabs, so test each tab with the account you plan to use.

Check delegation before you share access

Microsoft’s documentation is inconsistent on whether Consumption Dashboard access can be delegated. How to use the Consumption Dashboard says it can’t; Delegate access describes a Combined access scope that includes it. Test with a pilot delegate before you rely on either. Also review existing delegates: when a delegator has both company and group access, their Your company delegates move to Combined access automatically and might now see the Consumption Dashboard.

Named users and privacy

Copilot Analytics outputs, including the Consumption Dashboard, are de-identified by default. Identification lets authorised users see named employees in Consumption Dashboard insights and exports. It’s granted through its own Viva feature access management policy, which only a Global Administrator or AI Administrator can create. When identifiable export is on for a user, their exports include identifiable fields; otherwise identifiers are replaced with anonymised IDs. Identification is also listed for Copilot Dashboard data export (private preview) and Agent Dashboard data export, whose preview status Microsoft’s articles disagree on (Section 9).

The admin center report works differently. Its usage details table defines User ID as the user’s email address. Microsoft 365 usage reports hide user names by default through the Conceal user, group, and site names in all reports setting, but Microsoft doesn’t document how that setting, or the Identification policy, applies to the Cowork table and its export. Check both with the role you intend to use, and treat the output as personal data until you’ve confirmed what it contains.

4. Operating the Dashboards

Tasks 1–3 use the Microsoft 365 admin center. Task 4 uses Viva Insights.

Task 1 — Open the Cowork dashboard

  1. Sign in to the Microsoft 365 admin center with a reporting role from Section 2.
  2. In the left navigation, select Copilot.
  3. Under Copilot, select Cowork.
  4. Note the Last updated timestamp in the upper-right corner. It shows when the data was last refreshed; record it with every figure you take.

Verify: the dashboard opens and shows a Last updated timestamp.

Task 2 — Read the Overview and Usage tabs

  1. On Overview, read Active Cowork users and Total Cowork tasks. If a grace-period banner appears, note the date on the Grace period card.
  2. Under Top actions for you, review Pending requests for Cowork.
  3. Select Usage and set the Date range selector.
  4. Read the four cards: Active Cowork users, Total Cowork tasks, Average tasks, and Retained Cowork users.
  5. Review the Daily active users and Tasks by type charts. Tasks by type splits user-initiated tasks from scheduled ones.
  6. Review the Cowork usage details table for user-level activity.

Verify: when you change the date range, the cards, charts, and table all update.

A task is one conversation thread, whether a user started it or Cowork ran it on a schedule. Follow-up questions in the same thread don’t create a new task. Watch the ratio of Retained Cowork users (active in both of the last two seven-day periods) to Active Cowork users: a high ratio means people keep coming back.

Task 3 — Review the Value tab (Frontier preview)

The Value tab is a Frontier preview feature (Section 3). Read Section 5 before you quote any figure.

  1. In Copilot > Cowork, select the Value tab.
  2. Set the Date range to Last 28 days or Month to date. Both run to the latest available data refresh.
  3. Read the Cowork assisted hours card.
  4. Review Assisted hours by task category, which shows users, assisted hours, and credits spent for each category.

Verify: the card and table reflect the range you chose. If the tab is missing, check the Frontier setup in Section 3 and test with another eligible account; Microsoft doesn’t document exactly when the tab appears.

Task 4 — Read the Cowork page in the Consumption Dashboard

The Consumption Dashboard is on by default but needs usage-based billing set up through Cost Management in the Microsoft 365 admin center.

  1. Open the Consumption Dashboard in the Viva Insights web app.
  2. On the Microsoft 365 services tab, set Scope, Organization, and Job function. The time period is month to date.
  3. Select Deep dive next to Cowork.
  4. Read the cards: Cowork active users, Cowork Credit usage, and Average tasks per user.
  5. Use Cowork usage trends to see how credits and activity change over time by group, organisation, job function, or policy.
  6. Use Cowork usage breakdown by task to see which task categories consume the most.
  7. Switch Metric between credits used and task count.
  8. Review Usage intensity to see whether consumption is concentrated in a few users. It’s similar to the usage intensity view on the Microsoft 365 services page.

A high share of scheduled tasks in the breakdown can indicate that people are automating repeatable work.

Verify: the cards show month-to-date values and change when you change Scope, Organization, or Job function. For metric definitions, see Copilot Cowork metrics.

5. Reading Assisted Hours

Treat Cowork assisted hours as a directional estimate of the work Cowork supported. Never present it as time saved, a productivity gain, a business outcome, or money. The same caution applies to any assisted value shown on the Consumption Dashboard’s Cowork page.

  • How it’s calculated. Each task is matched to a type of work and assigned a typical time impact, informed by independent published research and observed usage patterns. The Cowork methodology (PDF) groups tasks into eight categories, each with a minutes-saved range traceable to a published study. Actual impact varies with the work and how people use Cowork.
  • It isn’t the Copilot Dashboard metric. Copilot Dashboard Assisted Hours applies research-based multipliers to Copilot actions, and Assisted Value applies an hourly rate ($72 by default). Cowork has no documented rate or currency. Don’t add, compare, or trend the two. The Dashboard Guide covers the Copilot Dashboard metrics.
  • Category names differ between Microsoft pages. The metrics reference lists a Document & comment task category; the Value tab and the methodology call it document and content creation. Map the labels before you compare reports (Section 9).
  • Don’t quote the methodology’s minute values. Its cover is labelled v4 but its page footers say v3 (additive), and the aggregation formula and the handling of unclassified tasks aren’t documented.

When you report assisted hours:

  1. Call it a directional estimate of work Cowork supported.
  2. Show it by task category, next to Credits spent for the same category and period.
  3. State the surface, date range, Frontier status, and methodology link with every figure.
  4. Don’t convert it to money.

6. Export and Reconciliation

Export from the admin center

  1. On the Usage tab, select Export above the Cowork usage details table.
  2. Save the CSV file. It includes every user in the table, with activity since 1 April 2026.

Verify: the number of rows matches the item count in the table header.

The file can identify users by email address (Section 2), so store it as personal data. Microsoft doesn’t document the CSV headers, encoding, or row limits.

Export from the Consumption Dashboard (public preview)

This export is a public-preview feature. Where it’s available, global-partition Insights Analysts and Global Administrators can use it, so confirm that the download button appears before you plan around it. The export involves personal data and excludes GitHub metrics. Whether managers can export is unresolved (Section 9).

OptionCoversTypical freshness
Export by weekThe previous five months plus month to date2–8 days behind
Export by dayThe start of the previous month to the export dateUp to two days behind

Both options include complete days or weeks only; an incomplete period is left out. Each download is a ZIP file with two CSV files that join on PeopleHistoricalId. PersonServiceCreditsMetrics.csv has one row per person, service, and date, with sessions and credits (for example SessionCount and TotalCreditsUsed). It doesn’t include Cowork tasks, task categories, or assisted hours. Identifiers are hashed unless identifiable export is enabled for you.

  1. At the top right of the Consumption Dashboard, select the download button.
  2. Select Export by week or Export by day.
  3. Join the two CSV files on PeopleHistoricalId only.
  4. Check the ServiceName values in your file and keep the Cowork rows. The export article’s example values are Copilot Cowork, WorkIQ, Researcher, BizChat, Deepwork, Outlook, and WXP, although the dashboard reports only Cowork and the Work IQ API.

Verify: the ZIP contains two CSV files that join cleanly on PeopleHistoricalId and include only complete days or weeks. Record the latest date in the file, because recent periods can be missing while they’re incomplete. Store the files under access controls suitable for personal data.

Reconcile the figures

Expect the numbers to differ. Tasks, credit sessions, and credits count different things, and the two products scope and time their data differently:

  • Tasks and sessions. The Consumption Dashboard article says several tasks, especially scheduled ones, can map to one billed session; the metrics reference defines a session as a task or conversation, including scheduled tasks. Treat the mapping as unresolved (Section 9).
  • Scope. Viva Insights follows Scope, Organization, and Job function; the admin center lists individual users. Microsoft documents a minimum group size for the Copilot and Agent Dashboards but doesn’t say whether the Consumption Dashboard suppresses small groups, so check in your tenant.
  • Active users. The admin center counts anyone who prompted a Cowork task or had a scheduled task run for them. On the Consumption Dashboard, compare against the Cowork page’s Cowork active users (people who used Cowork at least once in the period), not the services page’s Active users card, which also counts Work IQ API activity.
  • Time window. The Usage tab defaults to the past 28 days; the Consumption Dashboard shows month to date.
  1. Record the surface, tab, date range, scope, and filters with every figure.
  2. Compare like with like: admin center tasks with admin center tasks, and Consumption Dashboard credits with Copilot > Cost management credits for the same policy and period. Never compare task counts with session counts.
  3. Reconcile money only against the monthly billing record. Billing > Bills & payments in the Microsoft 365 admin center shows invoices and a high-level snapshot of charges; for detailed analysis by subscription, resource, meter, or invoice period, use Azure Cost Management.
  4. Log any difference you can’t explain rather than forcing the totals to match.

Verify: every difference has a stated cause or is logged.

7. Success Criteria

Before you rely on a recurring Cowork review, confirm that:

  • Each reviewer sees only the surfaces and scopes their role allows, and managers can’t switch to Company scope.
  • The spending policies that include Cowork cover exactly the people you intend.
  • The admin center tabs show a Last updated timestamp, and changing the date range updates every card, chart, and table.
  • The Value tab is visible after Frontier enrolment, or its absence is recorded, and every assisted-hours figure carries its date range, surface, and caveat.
  • The Consumption Dashboard Cowork page responds to the Scope, Organization, and Job function filters.
  • Exports are stored under personal-data access controls, and money is reconciled against the billing record.
  • Nobody has promised availability in GCC or any other national cloud.

8. Troubleshooting and Escalation

SymptomLikely causeFix
Someone can use Cowork who shouldn’tThey’re in scope of at least one spending policy that includes Cowork. A more restrictive policy doesn’t override a more permissive one.Find every policy that includes Cowork and remove them from its scope.
A low credit limit doesn’t stop a userLimits are a spending safeguard, not an access control. A one-credit limit still grants access, and because limits are enforced asynchronously, a user might start one or more tasks after reaching the limit. A running task can also finish after the limit is reached.Control access through policy scope, and expect some use after a limit is reached.
You need to block specific usersMicrosoft’s articles give different routes: Cowork common questions says to add users to a security group excluded from the Copilot experience; Cowork access controls says to leave them out of every policy that includes Cowork.Test your chosen route on a pilot user, confirm they’re out of every policy that includes Cowork, and record what worked (Section 9).
Users can request Cowork but can’t use itCowork is discoverable but usage-based billing isn’t set up, so users can request access in the app.Review Pending requests for Cowork on the Overview tab, then set up consumptive billing to grant access to approved users.
The Value tab is missingThe Value tab is a Frontier preview feature, and Microsoft doesn’t document which enrolment it needs or exactly when it appears.Check Frontier under Copilot > Settings > Copilot Frontier, allow time for Frontier features to reach users (it might take three hours), and test with another eligible account.
The Consumption Dashboard is blank or zeroUsage-based billing isn’t set up, there’s no Cowork activity this month, or filters exclude everyone.Confirm billing setup and month-to-date activity, then clear the filters.
The admin center table shows no namesUsage reports conceal user names by default. Microsoft doesn’t document exactly how that setting applies to the Cowork table.Check the Conceal user, group, and site names in all reports setting and test the table with the intended role. Change the setting only if your privacy policy allows.

Escalation evidence

Before you escalate, capture the tenant’s cloud, the viewer’s role, the surface and tab, the date range, scope, and filters, the Last updated timestamp, the spending policies that include Cowork (with their scope and limits), the exact error text, and any related Message Center or Service Health notice. Route role and policy issues to the Microsoft 365 administrator who owns Copilot settings, access and Manager settings issues to the Insights Administrator, billing differences to the billing administrator, and unresolved availability or data questions to Microsoft Support.
