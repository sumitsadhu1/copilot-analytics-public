Copilot Analytics with Agency-Default Views for Multi-Agency Single Tenant

Version: 1.2 | Author: Sumit Sadhu | Last validated: 2 October 2026

THIS GUIDE’S AUTHOR-CREATED ARCHITECTURE PATTERN
Default Priority is an editorial name created by this guide. It is not a Microsoft product, security, compliance, sovereignty, or licensing term. The companion Restricted Reporting pattern was formerly labelled “Isolation”; the old word remains in the existing filename and URL only for link stability. Microsoft documents the component capabilities, but does not document either combined pattern as an end-to-end security boundary.

This pattern intentionally accepts that some authorized users can obtain broader cross-agency or tenant-wide views. Manager hierarchy can establish a useful default scope, but it is not an authorization boundary. Viva Insights partitions limit rows and columns in an assigned analyst query workspace; separate controls govern Dashboard, Analytics Reports, Agent Dashboard, metrics export, delegation, manager access, privileged roles, downloaded results, and Power BI. Neither pattern creates cryptographic, tenant, product-security, or independently certified isolation.

Supported-environment and licensing gate:
Supported Microsoft 365 environments for Viva Insights features (30 September 2026) lists availability feature by feature for GCC Moderate (GCC-M) and GCC High (GCC-H). The Agent Dashboard, Copilot Dashboard metric export, the Consumption Dashboard and the Copilot Dashboard Readiness page are not available in either. Delegate access to dashboards is not available in GCC-M and is partial in GCC-H. Of the Copilot Power BI templates, only the Copilot business impact report is supported (GCC-M: yes; GCC-H: partial). Check the matrix for each feature before planning a government-cloud rollout. Microsoft’s feature access management article states that its access controls aren’t available in GCC High or DoD. For GCC, check the documentation for the specific app. Connect to the Agent Dashboard (2 September 2026) says Agent Dashboard is unavailable in national and regional clouds. Plan-level support does not establish feature parity. Verify the exact cloud, tenant UI, Message Center, assigned service plans, agent activity, and every required surface before design.

Microsoft pages describe the advanced-access threshold differently. Environment requirements for Viva Insights (12 May 2026) explicitly gives 30 Microsoft 365 Copilot + 20 Viva Insights as 50 assigned Viva Insights service plans; the Dashboard article (29 September 2026) describes 50 Copilot or 50 Viva Insights. Do not state that mixed assignments fail. Verify assigned plans and tenant availability. For Agent Dashboard, use the conservative feature-specific prerequisite of 50 Microsoft Copilot licences plus agent activity; a 50-Viva-Insights-only tenant must validate availability. Escalate a documented mismatch to Microsoft Support.
Organizational-data precedence gate:
Microsoft’s articles differ on whether an upload replaces Entra data. The Copilot Dashboard article says an upload “permanently changes the source” of the dashboard data from Microsoft Entra ID to the file, including the Scope and Organization filters, while the parallel-ingestion article says Entra can remain the source for ManagerId and Organization. Do not describe either behaviour as universal; treat the tenant’s Organizational data page as the authority. Uploaded values change the source for supplied dashboard attributes; parallel ingestion can keep or restore Entra for ManagerId and Organization; Microsoft 365 Profile precedence is separate. Before change, capture each required attribute, current source, owner, effective date, coverage, and target surface in Data Quality and Profile. Check Setup → Migration and imports, Message Center, and the actual tenant UI. Use Microsoft 365 Organizational Data Service (formerly Organizational Data in Microsoft 365) for new/edited uploads unless the tenant explicitly presents a supported legacy path. Use supported update/delete behavior, not dummy rows. Source basis: Use your organizational data in Microsoft 365 and Microsoft Viva (1 September 2026), Upload and maintain data through the Microsoft 365 admin center (13 August 2026), Use Microsoft Entra plus .csv files for parallel data uploads (7 July 2026), Import and manage your organizational data with a .csv file (27 August 2026), Import organizational data from Workday (27 August 2026; 100,000-user limit), and Import organizational data using API-based import (preview) (27 August 2026).

TL;DR — Agency-Default Views in Under a Day

Leverage native Copilot Dashboard scoping and delegation so each agency leader sees their own data by default — no lockdowns, no partitions required.

  1. Verify manager hierarchy — ensure each agency CEO is the top-level manager for their agency in Entra ID (Section 4.1)
  2. Enable AutoCxO & Delegation — agency CEOs auto-identified, then delegate down to VPs (Phase 1)
  3. Enrich org data (optional) — CSV or Entra attributes for department/location filtering within each agency view (Section 4.2)
  4. Configure Publish Reports — enable manager settings so filtered reports reach agency leaders automatically (Phase 3)
  5. Create partitions (optional) — for analysts who need focused query access within a single agency (Phase 4)

Time estimate: 2–4 hours for core setup (Phases 0–2). Add half a day if using partitions or CSV enrichment.

1. Executive Summary

This document provides an author-created reporting pattern for a single Microsoft 365 tenant that hosts multiple agencies, where each agency wants to see its own Copilot adoption and impact data by default and explicitly accepts broader authorized cross-agency or tenant-wide visibility.

Key Difference from Restricted Reporting:
Restricted Reporting applies group-scoped restrictions and partitioned analyst workspaces to reduce cross-agency reporting paths. This guide keeps eligible native features available because broader authorized visibility is accepted. Hierarchy provides a default view, not a security boundary.
Recommended Approach: Native Scoping + Optional Partitions
  1. Copilot Dashboard with “Your group” scope — agency leaders auto-identified; “Your group” shows their own hierarchy’s data (which scope the dashboard opens to is not stated by Microsoft — confirm in the tenant).
  2. Dashboard Delegation — CEOs delegate to VPs and directors for agency-scoped views; a delegate can’t delegate further.
  3. Publish Reports — filtered by manager hierarchy for automatic agency-scoped delivery.
  4. Partitions (optional) — for analyst-level deep dives scoped to a single agency; analysts may access multiple partitions if collaboration requires it.

How “Your Group” Scoping Works

The Copilot Dashboard identifies senior leaders using the Entra ID manager hierarchy (Auto CxO Identification). Automatic identification applies only to tenants with at least 2,500 Entra ID users and a majority single reporting line; within that, a separate agency’s top leader is identified as a senior leader only if that agency tree is at least 4% of the total tenant. Smaller tenants or sub-4% agencies must grant the CEO access manually — the “Your group” scope still works once access is granted. Leaders with access see two scopes:

ScopeWhat It ShowsDefault?
“Your group”Copilot data for all employees in the leader’s management chainNot stated by Microsoft — confirm the landing scope for each senior leader in the tenant (runbook Phase 1, verification step 3)
“Your company”Tenant-wide Copilot data across all agenciesAvailable via toggle; whether it is the landing scope is not stated by Microsoft — confirm in the tenant

When each agency CEO is the top of their hierarchy, “Your group” = their entire agency. Where the dashboard opens to this view (confirm in the tenant), it immediately satisfies the “see my agency data first” requirement without any lockdown.

What about “Your company”?
Agency leaders with a tenant-wide access source may be able to use “Your company” and see aggregate data across agencies. This pattern explicitly accepts that possibility (FR-06). If it is not acceptable, evaluate Restricted Reporting and its evidence gate.

5. Implementation Runbook

0 Phase 0: Pre-Flight Verification

Audit the current state before configuring anything.

  • Verify manager hierarchy: Confirm each agency CEO has no cross-agency manager relationship. Use Entra portal → Users → select each CEO → check Manager field. Run the PowerShell audit in Appendix A for bulk verification.
  • Confirm assigned service plans: Apply the conflict-safe licensing gate in Pattern Boundary & Release Gates. Verify feature presence after processing; do not infer failure from a mixed licence assignment.
  • Confirm supported environment: Record the exact cloud and verify Dashboard, Agent, export, Power BI templates, and organizational-data path in the tenant UI and Message Center.
  • Identify agency leaders: List each agency’s CEO and their direct reports (VPs). These will be the primary dashboard consumers and delegation targets.
  • Review current VFAM state: Microsoft 365 admin center → Settings → Microsoft Viva → Viva Insights → Turn Advanced Insights on or off. Document which features are currently enabled or disabled.
  • Check existing dashboard access: Microsoft 365 admin center → Settings → Microsoft Viva → Viva Insights → Manage access settings for Microsoft Copilot Dashboard. Note who currently has access.
  • Capture rollback baseline: Export policies, access, delegations, role/partition assignments, org-data source/quality, query assets, and Power BI permissions before change.

1 Phase 1: Enable Native Features

Enable only the eligible Dashboard features approved for this accepted-visibility posture. Agent Dashboard and metrics export require separate preview, cloud, privacy, and access decisions.

1.1 — Enable Auto CxO Identification

Dashboard auto-enablement (Auto CxO Identification) is on by default and is managed with PowerShell at tenant level only. Microsoft states that user- and group-level policies aren’t supported for this feature and won’t take effect. Run Get-VivaModuleFeaturePolicy -ModuleId VivaInsights -FeatureId AutoCxoIdentification (Appendix A.1) and confirm no disable policy exists. Microsoft’s feature table lists this control as “Copilot Dashboard Auto Enablement”.

This automatically identifies agency CEOs (and other senior leaders) based on the Entra ID hierarchy and grants them Copilot Dashboard access with the “Your group” scope.

1.2 — Enable Dashboard Delegation

Microsoft 365 admin center → Settings → Microsoft Viva → Viva Insights → Turn Advanced Insights on or off → Copilot Dashboard Delegation (listed in Microsoft’s feature table as “Viva Insights Web App Delegation”) → ensure set to On for Everyone.

This allows agency CEOs to delegate their dashboard view to their direct reports (VPs, directors). Delegates see the scope the CEO assigns when adding them; the CEO should select “Your group” to keep it agency-scoped.

1.3 — Enable Agent Dashboard

Only if the environment and tenant pass the gate: Agent Dashboard is preview. Treat 50 Microsoft Copilot licences plus agent activity as the conservative prerequisite, validate availability in Worldwide, and do not expect it in national or regional clouds. Scope access to the approved population; do not default to Everyone without a documented cross-agency agent-data decision.

1.4 — Metrics Export (optional)

Copilot metrics export is preview and is not partition-scoped. It requires separate eligibility/global-access validation and is unavailable in GCC. Enable only for an approved group after privacy review and negative testing of weekly/daily exports; otherwise disable CopilotMetricsReport (confirm the exact FeatureId with Get-VivaModuleFeature -ModuleId VivaInsights) and use governed reports.

After Phase 1 — Verification:
  1. Allow up to a week for AutoCxO to process (the criteria are evaluated weekly). If a CEO needs access sooner, add them to the access list manually.
  2. Check Manage access settings for Microsoft Copilot Dashboard — agency CEOs should appear in the list as auto-identified.
  3. Have an agency CEO navigate to insights.cloud.microsoft, note which scope the dashboard opens to (Microsoft does not state the landing scope), and confirm “Your group” is available and shows only their agency.
  4. Confirm the “Your group” employee count is in the expected range — note it reflects Copilot-licensed employees only, and groups below the minimum group size (default 10) show “--”, so it tracks licensed headcount, not raw agency headcount.

2 Phase 2: Configure Delegation & Manager Settings

Set up delegation so agency leaders can share their dashboard view with their teams.

2.1 — Agency CEO Delegates to VPs

Each agency CEO should:

  1. Navigate to insights.cloud.microsoft → Copilot Dashboard.
  2. Select Share (top right of the dashboard), then Add delegates. You can also use Settings → Delegation.
  3. Add their direct reports (VPs, directors) as delegates (maximum 75; a delegate can’t delegate further).
  4. Delegates will receive access and see the scope the CEO assigns (select “Your group” to give the same agency-scoped view).

2.2 — Enable Manager Settings for Publish Reports

Navigate to insights.cloud.microsoft → Admin → Manager settings.

  • Select Grant managers scoped access to Copilot insights. Enabled managers can then see team-scoped Copilot Dashboard insights and receive manager-filtered published reports. Review the optional Grant managers scoped access to Consumption insights setting.
  • Set the minimum team size (at least five). This is a separate setting from the minimum group size privacy threshold: team size decides which managers are eligible, whereas group size hides small groups in insights.
  • Agency CEOs whose team size is at or above the minimum team size are eligible to receive published reports filtered to their hierarchy.

2.3 — Enrich Organizational Data (Optional)

  • Entra is the default source for ManagerId and Organization. Use Configure Entra connection only if the tenant’s current source is uploaded data (parallel ingestion); check the Organizational data page before changing it.
  • If you need custom attributes, first record current source precedence and confirm the tenant-supported upload path; then prepare the data per Appendix B. Uploaded attributes enrich filters but do not govern all access surfaces.
After Phase 2 — Verification:
  1. Have a VP who was delegated access navigate to the dashboard. Confirm they see their agency’s data.
  2. If org data was uploaded, verify the Organization filter on the dashboard, and the Job function filter if FunctionType (or Microsoft_JobDiscipline for Microsoft 365 admin center uploads) was supplied. Other attributes such as Location are available to analysts, not as dashboard filters.

3 Phase 3: Publish Reports

Use Viva Insights Publish Reports to deliver curated analytics to agency leaders automatically.

3.1 — Run Copilot PBI Template Queries

  • Insights analysts (Central IT or agency-level) navigate to insights.cloud.microsoft → Create analysis.
  • Select a Copilot Power BI template (Copilot adoption report, Copilot impact report, Copilot business impact report, etc.).
  • Run the query. If partitions are enabled, run within the appropriate partition. If not, run against the global population.

3.2 — Publish with “Filter by Manager Hierarchy”

  • After the query completes, select Publish report.
  • Choose “Filter report by manager hierarchy”.
  • Each enabled manager (CEO, VP) will receive a version of the report filtered to their team.
  • Set an expiry date (up to 365 days) and republish monthly to keep data current.
Why this is eligible in Default Priority:
This pattern accepts tenant-wide visibility from documented access sources. Manager publishing is still a separate surface: pilot a shared executive and cross-agency manager, verify Dashboard and report scope, capture evidence, and roll back manager enablement if observed access exceeds the approved posture.

4 Phase 4: Partitions for Analyst Deep Dives (Optional — Mandatory for CIO Reporting)

If your organisation has designated analysts per agency who need to run custom queries, partitions provide row/column-scoped analyst workspaces. This phase is optional for agency-level reporting (dashboard views and published reports may suffice), but needed for the cross-agency query approach described for CIO reporting. A global partition is tenant-wide and requires explicit conflict-of-interest and least-privilege approval. See Section 6.2.

Before Enabling Partitions:
(a) Understand that turning partitions on cannot be undone without contacting Microsoft support, and that analysts who already held the Insights Analyst role keep global partition access automatically until you remove it.
(b) Export all existing query results before enabling partitions.
(c) Partitions are needed when analysts require row/column-scoped custom query workspaces. Dashboard and manager-published views may follow hierarchy, but their actual scope must be tested separately.
  • Navigate to insights.cloud.microsoft → Admin → Privacy settings and turn on partitions, then open Partitions under Settings.
  • Select Create new partition and create a partition per agency (e.g., “Agency A”), filtered by Agency attribute (CSV) or Domain (Entra).
  • Assign agency analysts to their primary partition.
  • Cross-agency access: Analysts may be assigned to multiple partitions only with a documented business purpose, conflict-of-interest review, expiry, and quarterly recertification.
  • Assign Central IT analysts to the Global Partition for tenant-wide queries.
After Phase 4 — Verification:
  1. Have an agency analyst sign in and confirm they see their agency’s partition in the partition switcher.

6.1 ROI Analysis per Agency: Capabilities & Gaps

Agency leaders asking “What is Copilot’s ROI for my agency?” will find that some metrics scope naturally to their hierarchy and some do not. Set expectations upfront using the matrix below.

Which ROI Metrics Are Agency-Scoped?

ROI MetricScoped to “Your group” (Agency)?Notes
Copilot Assisted Hours ✅ Yes Impact page shows Assisted Hours for the leader’s management hierarchy. Agency CEOs see their agency’s total.
Copilot Assisted Value ✅ Yes Calculated as Assisted Hours × Hourly Rate. Scoped to “Your group.” However, the hourly rate is a single tenant-wide setting (see limitation below).
Adoption metrics (active users, usage intensity, consistent usage) ✅ Yes Adoption page can be scoped to “Your group” with the Scope filter (whether the dashboard opens to it by default is not stated by Microsoft — confirm in the tenant).

Limitation: Single Tenant-Wide Hourly Rate
Copilot Assisted Value is calculated as Assisted Hours × Hourly Rate. The hourly rate defaults to $72/hour and can be changed only in-session via the dashboard’s Hours and value calculator; the change is not saved and resets to the default each time the dashboard is reopened. It applies to all employees across all agencies — there is no way to persist or set different rates per agency, department, or role.

Impact: If Agency A’s average loaded labour rate is $140/hr and Agency B’s is $65/hr, the Assisted Value figure shown to both CEOs uses the same rate — making one agency’s ROI appear over- or under-stated.

Workaround: Use Power BI templates in partitions (Phase 4) to apply agency-specific hourly rates in the Power BI calculation layer. The raw Copilot Assisted Hours data flows into the PBI template; the analyst replaces the default rate with the agency’s actual loaded labour rate in a DAX measure or parameter. This produces accurate per-agency Assisted Value figures outside the dashboard.

Limitation: Dashboard ROI History Is Limited
The Copilot Dashboard metric cards use a 28-day rolling window, but in tenants with at least 50 assigned Copilot or Viva Insights licences the Adoption and Impact pages also show six-month trendlines (weekly or monthly) by group, organisation, job function or licence type, including Copilot assisted hours, assisted value and satisfaction rate. Agency leaders who need ROI history beyond six months, or agency-specific hourly rates, cannot get it from the dashboard alone.

Workaround — Recommended for ROI-focused agencies: Use Power BI templates within partitions (Phase 4). Run the Copilot impact report or Copilot business impact report template monthly, each time capturing the month’s metrics. Publish each refresh as a new dataset snapshot in the agency’s Power BI workspace. Stack monthly snapshots in a summary report to build a quarter-over-quarter ROI trendline.

Implication: For agencies that need ROI history beyond the dashboard’s six-month trendlines, or agency-specific hourly rates, Phase 4 (partitions) becomes a required component of the architecture. Plan the partition and analyst setup accordingly.

Recommendation for ROI-Focused Multi-Agency Deployments
  1. Dashboard for real-time adoption & current-month ROI: Agency CEOs use the Copilot Dashboard (“Your group”) for live adoption metrics and this month’s Assisted Hours/Value.
  2. Partitions + PBI for accurate, historical, agency-calibrated ROI: Treat Phase 4 as mandatory. Analysts run monthly PBI template queries within their agency partition, apply agency-specific hourly rates, and build cumulative ROI reports.
  3. Billing Playbook for cost-side data: Combine the Assisted Value from PBI reports with licence cost data from the Lifecycle & Billing Playbook to produce a net ROI figure per agency.

Manager hierarchy misconfigured — CEO-A’s “Your group” includes Agency B employees Medium Quarterly hierarchy audit. Run PowerShell report to verify tree boundaries. Since cross-agency visibility is acceptable, impact is operational (confusing data) rather than a compliance breach.
AutoCxO identifies unintended users as senior leaders Low Quarterly review of dashboard access list. Remove any incorrectly identified users. AutoCxO uses hierarchy depth, not job title — a shallow tree may identify mid-level managers.
Agency leader toggles to “Your company” and sees data they find confusing (not sensitive, but unexpected) Low Include user guidance: “Your group = your agency. Your company = entire tenant.” Tell leaders which scope the dashboard opens to in this tenant (Microsoft does not state a default landing scope; confirm it in the tenant) and set expectations during onboarding.
Delegation extends too far — low-level managers, or a broader scope than intended, get dashboard access Low Delegation does not chain: a delegate cannot delegate further, and each leader can have at most 75 delegates. Communicate delegation best practices (select “Your group” scope; delegate only to people who need it) and review the AddDelegates and RemoveDelegates events in the Microsoft Purview audit log quarterly.

10. Discovery Questions

  1. Which cross-agency and tenant-wide views are explicitly acceptable, by actor and surface? If the requirement is tenant, cryptographic, sovereign, or certified security isolation, stop and obtain a security architecture assessment; Restricted Reporting is only defense-in-depth reporting segmentation.
  2. How is the Entra ID manager hierarchy structured? Does each agency CEO sit at the top of an independent tree, or is there a shared parent?
  3. How many agencies, and how many employees per agency? (Each agency needs enough employees to meet the minimum group size threshold for “Your group” to display data.)
  4. Do agency CEOs want to delegate dashboard access to their VPs and directors? (Determines whether to actively configure delegation in Phase 2.)
  5. Are there shared-services teams? Where should they appear — in an agency’s “Your group,” or only in the “Your company” view?
  6. Do you need custom analytical filters (Department, Location, Job Function)? (Determines whether to enrich with CSV org data.)
  7. Will dedicated analysts per agency run custom queries? (Determines whether to enable partitions in Phase 4.)
  8. Are any shared executives, cross-agency managers, global-partition analysts, or analyst conflicts of interest present? Record and test their expected access explicitly.
  9. What is the minimum privacy threshold (minimum group size) acceptable to all agencies? (Tenant-wide setting — all agencies must agree.)
  10. Are Copilot agents deployed across agencies? Agent Dashboard is preview, not partition-scoped, and unavailable in national/regional clouds. Confirm eligibility, approved audience, privacy posture, and tested scope before enabling it.
  11. What exact cloud and preview capabilities are supported? Validate Agent Dashboard, metrics export, Copilot Power BI reports, and organizational-data paths against the current matrix and tenant UI.
