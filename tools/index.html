1. Where This Page Fits — The Reporting Estate

Microsoft documents four main sources for Copilot usage reports. They are not substitutes for one another: each covers a different population, permission model, data shape, latency, and authority. Establish which source a figure came from before it reaches a report.

SourceWhat Microsoft documents it forDocumented access
Microsoft 365 admin center Readiness and usage reports focused on licence eligibility, adoption, and basic usage metrics. AI Administrator accesses the Copilot reports.
Copilot Analytics, powered by Viva Insights The Copilot Dashboard and the Advanced Insights Analyst workbench, for detailed metrics and custom reporting. AI Administrator enables the Dashboard and delegates access; Global Administrator assigns the Insights Analyst and Insights Administrator roles. Microsoft notes some admins may receive Dashboard access automatically.
Microsoft Purview audit logs Detailed audit logs of Copilot activities, for compliance tracking and security auditing. Audit Reader searches the audit logs; other roles can also search.
Power Platform and Copilot Studio Analytics Consumption metrics for agents through the Power Platform admin center, and per-agent performance analytics in Copilot Studio. Copilot Studio authors see analytics for the agents they create; Power Platform Administrators can view analytics for all agents in the tenant.

Sources: Microsoft Copilot reporting options for admins (Last updated 17 September 2025) and Monitor overview (Copilot Studio) (Last updated 25 August 2026).

Sequence this project recommends

This ordering is editorial, not a Microsoft maturity model

Microsoft documents the four sources above as parallel reporting options, not as stages. The order below is this project’s recommendation for a first rollout, based on the prerequisites each surface carries. Do not present it to a customer as Microsoft guidance.

OrderSurfaceWhy hereGuide in this hub
1 Microsoft 365 admin center readiness and usage reports Requires no organizational-data upload and no Viva Insights configuration. The cheapest signal available on day one. Admin Setup
2 Copilot Dashboard Depends on organizational-data quality, scope configuration, and minimum group size. Fix those first, or the Dashboard will report a confidently wrong shape. Data Onboarding, then Dashboard & Reports
3 Consumption Dashboard and Power Platform admin center Only relevant once agents or consumption-based billing are live. Official charges remain in the billing portal, not in an analytics view. Consumption Dashboard Operations, Billing Operations
4 Advanced Reporting queries and Power BI templates Settle metric definitions, partitions, and privacy settings first. Building custom reports before that industrialises a disagreement about what the numbers mean. Analyst Playbook
5 Microsoft Purview audit Event semantics, retention, latency, and privacy treatment all differ from adoption reporting. Use it for compliance and investigation, not for adoption trend lines. Analyst Playbook § Programmatic reporting

4. Quick Decision Checklist

  1. Define whether the question is about billing, consumption, adoption, impact, value, or audit.
  2. Define the required population: licensed Copilot users, unlicensed Copilot Chat users, a partition, a manager group, or all covered events.
  3. Confirm the least-privileged role or API permission and the supported cloud environment.
  4. Record the source, scope, period, refresh timestamp, identifiers, and privacy treatment with every output.
  5. Reconcile against the authoritative surface: billing portal for charges, source report for adoption, or Purview for audit events.
  6. Do not combine sources until metric definitions, time boundaries, and identity handling are explicitly mapped.

6. Related Open-Source Tooling

This project publishes guidance only — it ships no reports. Once a surface is configured and you need something to run against it, Microsoft publishes an open-source catalogue of Power BI templates, exporters, and browser apps at Analytics Hub (microsoft/Analytics-Hub).

Outside this project’s evidence process — evaluate before you run anything
  • These are open-source projects published in Microsoft’s GitHub organisation. Several of their READMEs state they are not supported through Microsoft support channels, and some are labelled experimental. Confirm each project’s licence, ownership, and support terms yourself.
  • They are not covered by this project’s Microsoft Learn drift checks. The summaries below are the publishers’ own descriptions, not this project’s assessment. Links were checked on 2 October 2026.
  • Several read Microsoft Purview audit data, which can include prompt content. Treat that as a materially higher privacy classification than Dashboard adoption metrics and clear it through the same review you would apply to any user-level export. See Privacy Configuration.
  • Consumption Central’s README tells admins to turn on Viva Identification (a Viva feature access management policy created by a Global Administrator or AI Administrator) for per-person or department views. Identification surfaces named employees; treat the output as personal data and apply your own review.
  • Review the source, the permissions requested, and where outputs are written before running anything against a production tenant.
